# ADR-0001. Блокировка мест реализована через статус в сущности «Место»

**Дата:** 2026-10-06
**Статус:** принято

## Контекст
Когда зритель выбирает билеты на стадион и переходит к оплате, выбранные места не должны быть доступны другим пользователям. Требуется механизм временного резервирования, чтобы избежать двойных продаж одного и того же места.

## Рассмотренные варианты
1. Ввести отдельную сущность `Reservation` (Бронь) со временем жизни (TTL), которая ссылается на место.
2. Добавить статус `LOCKED` (Заблокировано) непосредственно в `enum` статусов сущности `Seat` (Место).

## Решение
Вариант 2 (Добавление статуса `LOCKED` в сущность `Seat`).

## Последствия
**Плюсы:** простота реализации, не требуется создавать новые таблицы в БД и усложнять доменную модель. Легко проверять доступность места при отрисовке схемы зала.
**Минусы:** для снятия просроченных блокировок потребуется фоновый планировщик, который будет регулярно сканировать таблицу мест на наличие зависших статусов `LOCKED`.
**Что станет неверным, если решение пересмотреть:** диаграмма классов (удалится статус из enum), диаграмма состояний автомата и динамический вид С4.
